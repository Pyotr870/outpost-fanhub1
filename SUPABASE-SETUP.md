# OUTPOST 0.8 — подключение облака Supabase

Эта сборка содержит интеграцию с Supabase, но **облако не включится само**: нужен собственный проект и его публичные клиентские параметры. Я не создавал аккаунт и не подключал платёжные данные.

## 1. Создать проект
1. Открой [Supabase](https://supabase.com/) и войди в аккаунт.
2. Создай Organization и Project. Для первого теста выбери Free.
3. Регион выбирай ближе к основной аудитории проекта; регион можно изменить только через перенос/новый проект.
4. Сохрани пароль базы данных в менеджере паролей — не отправляй его в чат и не вставляй в сайт.

## 2. Создать таблицы и приватное хранилище
1. Открой проект → SQL Editor → New query.
2. Скопируй весь `schema.sql`, выполни запрос.
3. Проверь, что созданы `profiles`, `albums`, `photos` и приватный Storage bucket `outpost-photos`.

## 3. Подключить сайт
1. В Supabase открой Project Settings → API (или API Keys).
2. Скопируй Project URL и **publishable key** (или legacy anon key).
3. Открой `supabase-config.js` и вставь значения в `url` и `anonKey`.
4. Вставлять можно только publishable/anon key. **Никогда не вставляй `service_role`, secret key или пароль базы данных в JavaScript, HTML, GitHub или чат.**
5. Перезагрузи сайт через HTTPS-хостинг. `file://` для реального облачного входа не подходит.

Пример (значения ниже фиктивные):
```js
window.OUTPOST_SUPABASE_CONFIG = {
  url: "https://your-project.supabase.co",
  anonKey: "YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY"
};
```

## 4. Настроить Auth
1. Supabase → Authentication → URL Configuration.
2. Укажи адрес опубликованного OUTPOST как Site URL и добавь его в Redirect URLs.
3. Оставь подтверждение email включённым. Для публичного запуска настрой собственный SMTP-провайдер, иначе письма могут иметь строгие лимиты.
4. Проверь регистрацию, письмо подтверждения, вход, выход и сброс пароля.

## 5. Что уже реализовано в 0.8
- Регистрация и вход по email/паролю через Supabase Auth, когда заполнена конфигурация.
- Профиль авторизованного пользователя и выход.
- Загрузка локальных снимков в приватный Storage.
- Отдельная облачная галерея с избранным, коллекциями, скачиванием и удалением.
- SQL-политики RLS: каждый пользователь видит только собственные записи и файлы.

## Важно о безопасности
- В `supabase-config.js` разрешён только публичный publishable/anon key. Безопасность обеспечивают RLS-политики, а не секретность этого ключа.
- Не отключай RLS и не делай bucket публичным.
- Не загружай фотографии других людей без их согласия.
- Перед реальным запуском нужны проверка политики доступа, ограничения частоты запросов, правила удаления аккаунта и privacy policy.
- Сейчас нет публичных альбомов, комментариев, поиска чужих профилей, Discord OAuth, Steam OpenID или автоматического чтения фото из игры.

## Тестовый сценарий
1. Зарегистрируй отдельный тестовый аккаунт.
2. Подтверди email и войди.
3. Импортируй тестовое изображение в локальную галерею.
4. Нажми «Загрузить мои локальные фото».
5. Открой сайт в другом браузере/устройстве, войди в тот же аккаунт и скачай файл из облачной галереи.
6. Создай коллекцию, назначь её фотографии, отметь фото избранным, удали тестовый снимок.
7. Создай второй тестовый аккаунт и проверь, что он не видит фотографии первого.

Если любой пункт приватности не проходит — не открывай регистрацию публично, пока политика доступа не исправлена.

## OAuth-провайдеры (Google / Discord / GitHub / Apple)

В OUTPOST 0.8 окно входа показывает отдельные кнопки Google, Discord, GitHub и Apple. Они вызывают Supabase OAuth (`signInWithOAuth`) и не собирают пароли этих сервисов.

Чтобы включить конкретный способ входа:
1. Создай OAuth-приложение у выбранного провайдера и получи Client ID / Client Secret.
2. В Supabase открой Authentication → Providers и включи соответствующего провайдера, добавив его Client ID / Secret.
3. В OAuth-приложении укажи callback URL Supabase, показанный на странице провайдера в Supabase (обычно `https://<project-ref>.supabase.co/auth/v1/callback`).
4. В Supabase → Authentication → URL Configuration добавь адрес опубликованного OUTPOST в Site URL и Redirect URLs.
5. Сохрани настройки и протестируй вход с отдельной тестовой учётной записью.

Пока проект Supabase не создан и провайдеры не настроены, кнопки показывают объяснение и не выполняют вход. Это ожидаемое поведение, а не фиктивная авторизация.

### Steam
Steam не является встроенным OAuth-провайдером Supabase. Для настоящего Steam-входа требуется отдельный серверный маршрут, который выполняет Steam OpenID и проверяет ответ Steam на сервере. Нельзя запрашивать у пользователя пароль Steam или проверять его на стороне браузера. В версии 0.8 Steam-вход не заявляется как подключённый.
